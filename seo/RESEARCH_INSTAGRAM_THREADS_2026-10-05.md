# Исследование: автоматизация Instagram и Threads как услуга

**Дата:** 05.10.2026 · **Статус:** валидация 06.10.2026 — вердикт в `VALIDATION_INSTAGRAM_THREADS_2026-10-06.md` (идея в исходной формулировке ошибочная; узкая версия — слабый фит, решение владельца)
**Интент от владельца:** поиск постов по ключевым словам, поиск людей по описанию профиля, автоматизированные сообщения им. Гипотеза: реализуется через ИИ-агентов и MCP, можно продавать как услугу и сделать посадочную.

---

## TL;DR — резюме для решения

1. **Технически всё реализуемо, но официально — только частично.** Главный подводный камень: холодная массовая рассылка в Директ запрещена правилами Meta и через официальный API невозможна в принципе. Продавать «бот пишет незнакомым людям в личку» нельзя — это прямой путь к бану клиентского аккаунта и репутационным потерям.
2. **Threads — самая сильная и честная точка входа.** У официального Threads API есть поиск публичных постов по ключевым словам, автоответы и вебхуки. Конкуренции по этой теме в выдаче практически нет — формат новый.
3. **Instagram официальный API узкий:** поиск постов только по хэштегам (макс. 30 тегов / 7 дней), поиска людей по описанию профиля нет, ДМ-автоматизация — только по инициативе пользователя (окно 24 ч). «Поиск по ключевым словам» и «люди по био» — только через парсинг (серая зона: Apify и аналоги).
4. **MCP** — рабочий слой интеграции, но официального MCP-сервера от Meta нет; community-серверы либо оборачивают официальный Graph API (безопасно), либо приватные API (бан-риск). Свой MCP-сервер поверх официальных API — 1–2 дня работы и хороший дифференциатор («ИИ-агент ведёт ваш Instagram»).
5. **Рекомендация:** продавать связку **«Instagram-автоматизация заявок (официально) + Threads-мониторинг спроса (ранний доступ)»**. Посадочную создавать можно уже сейчас — но под легальную часть интента. Аутрич/лидгены — как отдельная услуга «по запросу» с явными рисками, где отправку сообщений делает человек, а ИИ готовит персонализированные черновики.

## 1. Официальные API (проверено по документации Meta, 05.10.2026)

### 1.1. Threads API — самое сильное из двух

| Возможность | Есть? | Детали / лимиты |
|---|---|---|
| Публикация постов | ✅ | до 250 постов / 24 ч на профиль |
| Ответы на публичные треды | ✅ | до 1 000 ответов / 24 ч |
| Модерация ответов | ✅ | скрыть/удалить, фильтры |
| **Поиск публичных постов по ключевым словам** | ✅ | `/keyword_search`: TOP/RECENT, фильтры по типу медиа, дате и **author_username**; в ответе — текст, username, пермалинк, timestamp. Лимит **2 200 запросов / 24 ч** (скользящее окно; сторонние источники за 2026 называют и 500/7 дней — лимиты периодически пересматривают, проверять перед реализацией) |
| Вебхуки (упоминания, ответы) | ✅ | реакция в реальном времени |
| Личные сообщения | ❌ | в Threads их нет как продукта — «писать в личку» там невозможно технически |

**Важные условия:** нужны permissions `threads_basic` + `threads_keyword_search`; **до аппрува приложения поиск работает только по своим постам**, после — по публичным. Чувствительные слова возвращают пустой ответ.

**Вывод:** связка «мониторинг ключей ниши → алерт в Telegram → ИИ-черновик ответа» — это готовый продукт на официальном API. Пример: мастер по ресницам получает в Telegram все новые треды «ищу ламинирование Минск» с юзернеймом и пермалинком.

### 1.2. Instagram Platform API

| Возможность | Есть? | Детали / лимиты |
|---|---|---|
| Поиск постов по ключевым словам | ❌ | только **Hashtag Search**: top/recent по тегу, макс. **30 уникальных тегов / 7 дней** на аккаунт; нужны Business/Creator-аккаунт + App Review |
| Business Discovery | ✅ | публичные данные бизнес-аккаунтов (ограниченные поля), ~200 вызовов/час × DAU приложения |
| Поиск людей по описанию профиля | ❌ | официального эндпоинта нет |
| Basic Display API | — | закрыт с 04.12.2024 |
| **Директ (Messenger API for Instagram)** | ⚠️ | **только user-initiated**: окно 24 ч после последнего сообщения пользователя; Human Agent tag — до 7 дней; ~200 ДМ/час через одобренные инструменты. **Холодный аутрич API не предусматривает** |
| Комментарии | ✅ | чтение/ответ — на этом строятся воронки «комментарий → ДМ» |

**Вывод:** «поиск постов по словам» и «люди по био» в Instagram официально недоступны — это осознанное ограничение Meta (защита от спама). Всё, что так умеет, — приватные/скрейперные методы.

### 1.3. MCP-экосистема

- **Официального MCP-сервера от Meta нет** (на 05.10.2026).
- Community-варианты: `ig-mcp` (обёртка официального Graph API для бизнес-аккаунтов — безопасно), скрейперные MCP через Chrome-сессию или `instagrapi` (работают, но бан-риск на аккаунте), комбинированные «Meta Platform»-серверы (Graph + Threads).
- MCP — правильный слой для агентов, но ценность создаёт не он, а интеграции под ним. Свой MCP поверх официальных API — дёшево и без рисков.

## 2. Серая зона: парсинг и аутрич

- **Apify Instagram Scraper** и аналоги (2026, работают): поиск по ключевым словам, парсинг профилей/био (email, телефоны), хэштегов, комментариев. Стабильность высокая, но это нарушение ToS Meta.
- **instagrapi / приватные API:** бан-риск высокий, сессии регулярно ломаются после обновлений Instagram.
- **Риски:** блокировка аккаунта, с которого парсят (потеря технического акка — недорого, но постоянно); качество/актуальность данных; GDPR для европейской аудитории; в BY юридическое давление низкое, но репутационный риск для исполнителя — реальный.
- **Рабочее правило:** парсинг — с отдельных «технических» аккаунтов, результат = лид-листы; **отправку сообщений автоматизировать нельзя**, только человек с ИИ-черновиками.

## 4. Упаковка: три продукта

### A. «Instagram-автоматизация заявок» — ядро, легально
- Воронка «комментарий по ключу → ДМ» и ДМ по ключевым словам — официальный, одобренный Meta сценарий (так работают ManyChat и ко).
- Заявки из Директа → Telegram/CRM, теги, уведомления.
- ИИ-черновики ответов с человеком в контуре.
- **Дифференциатор против конструкторов:** своя интеграция на официальном API — **без абонплаты за каждого подписчика** (боль ManyChat при росте базы). Продолжение текущего УТП сайта «без абонплаты».
- Цена по аналогии с «Автоматизацией заявок»: от 500–700 BYN.

### B. «Threads-мониторинг спроса» — ранний доступ
- Мониторинг ключевых слов ниши → алерты в Telegram → ИИ-черновики ответов (отправка вручную или автореплай в лимитах).
- Формат новый: в RU/BY-выдаче по «threads автоматизация / продвижение в threads» игроков практически нет — шанс занять нишевые запросы первому (по аналогии с кейсом krupki-master.by).
- Честная оговорка на посадочной: «формат молодой, аудитория Threads в BY меньше, чем у Instagram» — работает на доверие, как «честно про границы формата» на странице лендинга.

### C. «Лидгены по аудитории» — серая зона, только по запросу
- Лид-листы (ниша + гео + ключи в био) через Apify в Google Sheets.
- ИИ-персонализация сообщений, **отправляет человек**.
- На посадочной это не рекламировать: репутационный риск + не проходит по позиционированию «работаем в рамках официальных API».

## 5. Риски и договорённости

- **Бан клиентского аккаунта** — главный риск. Зафиксировать в договоре/оффере: работаем в рамках официальных API; за контент и ручные действия отвечает клиент, за технические лимиты — исполнитель.
- **App Review Meta** для ДМ-сценариев: бизнес-верификация + демо-видео, 1–4 недели. Нужен собственный Meta-аккаунт разработчика (решение — см. открытые вопросы).
- **Rate limits** → проектировать очереди и «человеческие» темпы сразу.
- **Персональные данные** при лид-листах: хранить минимально, не перепродавать.

## 6. Спрос и конкуренты

- Рынок чат-ботов для Instagram активен и растёт: ManyChat (официальный партнёр Meta), BotHelp, Salebot, ChatPlace, SendPulse — все продают **конструктор с абонплатой**. Ниши «под ключ + без абонплаты + заявки в Telegram + Беларусь» в выдаче практически пусты (паттерн, повторяющий успешные кластеры сайта).
- Многие инструменты недоступны для оплаты из BY — аргумент в пользу «своей интеграции под ключ».
- **Ключи для проверки в Wordstat** (перед написанием текстов посадочной): `автоматизация инстаграм`, `чат-бот для инстаграм`, `автоответы в директ`, `воронка инстаграм`, `интеграция instagram с crm`, `парсинг подписчиков инстаграм`, `лидогенерация инстаграм`, `продвижение threads`, `threads автоматизация`.
- Каналы: посадочная + 2–3 статьи блога («Как собрать воронку комментарий → ДМ без ManyChat», «Мониторинг спроса в Threads: инструкция», «Почему холодные рассылки в Директ убивают аккаунт»).

### 6.1. Проверка широты спроса (база Bukvarix, 05.10.2026)

Yandex Wordstat программно недоступен (требует логина Яндекса — прямой запрос вернул 404), точные частотности Bukvarix отдаёт только в JS-таблице. Поэтому широта семантики проверена по числу связанных ключей в открытой базе Bukvarix (регион «Весь мир») — это прокси-метрика охвата спроса, не точный объём:

| Фраза | Связанных ключей в базе | Сигнал |
|---|---|---|
| чат бот инстаграм | **212** | широкое ядро — самый большой кластер, включать в семантику посадочной и блога |
| воронка инстаграм | **140** | широка — воронки ищут активно, вторая статья для блога |
| автоматизация инстаграм | **47** | средне — целевой транзакционный кластер, хватит на посадочную |
| instagram автоматизация (латиницей) | 14 | узко, вторично |
| threads продвижение | **0** | темы нет даже в базе → выдача пустая, шанс first-mover, но трафик из Яндекса пока не ждать |
| чат-бот инстаграм (с дефисом) | 0 | артефакт матчинга дефиса — в текстах опираться на написание «чат бот» без дефиса |

**Интерпретация:** спрос существует и шире целевой фразы — основные кластеры «чат бот инстаграм» и «воронка инстаграм». Это меняет семантику посадочной: H1 можно строить на «чат-бот для Instagram», а «автоматизация» — вторым вхождением. Для Threads-части честное ожидание: трафик из Google, соцсетей и прямых заходов, не из Яндекса.

**Чек-лист ручной проверки (Wordstat, регион «Беларусь»):** `автоматизация инстаграм`, `чат бот инстаграм`, `воронка инстаграм`, `автоответы в директ`, `интеграция instagram с crm`, `парсинг подписчиков инстаграм`, `лидогенерация инстаграм`, `threads продвижение`. Вписать точные частотности в таблицу выше перед написанием текстов посадочной.

## 7. Оценка MVP

| Компонент | Срок | Комментарий |
|---|---|---|
| Threads-мониторинг (поиск → Telegram-бот → черновики) | 3–5 дней | нужен Threads-апп + permission; поиск публичных постов — после аппрува |
| Instagram «комментарий → ДМ» + заявки в Telegram | 1–2 недели | упирается в App Review Meta |
| MCP-сервер для ИИ-агентов поверх интеграций | 1–2 дня | после готовности интеграций |
| Лидгены через Apify | 1–2 дня | по запросу, вне публичного оффера |

Стек уже есть: Next.js, Telegram-боты, cron/VPS.
